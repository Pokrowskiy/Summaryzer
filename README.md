# Summarizer

Полностью локальное приложение для для автоматической диаризации, транскрипции и суммаризации совещаний с использованием моделей **Pyannote 3.1**(диаризация), **Faster-Whisper**(STT) и **Qwen 2.5**(Анализ расшифровки).

## Требования для работы

* **ОС:** Windows 10/11 (из-за использования VBS-скриптов запуска)

* **Python:** 3.12.0 - 3.12.9 (Рекомендуемая версия, запуск на других может вызвать ошибки совместимости)

* **CPU:** Intel Core i5 2.7 GHz

* **Дискретная GPU:** От 4 ГБ VRAM (для стандартной модели. Замена LLM на более мощную может повысить требования к ресурсам системы).
ИЛИ 
* **Встроенная GPU:** От 8 ГБ RAM (Встроенная GPU использует общую RAM)

* Активный `HF_TOKEN` (Hugging Face) с доступом к моделям :
    - `https://huggingface.co/pyannote/speaker-diarization-3.1`

    - `https://huggingface.co/pyannote/segmentation-3.0`

    - `https://huggingface.co/pyannote/speaker-diarization-community-1`

## Быстрый старт

### 1. Подготовка окружения

1. Склонируйте репозиторий.

2. Создайте виртуальное окружение:

```
python -m venv venv
venv\\Scripts\\activate
```

3. Установите зависимости:

```
pip install -r requirements.txt
```

### 2. Настройка переменных (`.env`)

Создайте файл `.env` в корневом каталоге:

```
HF_TOKEN=ваш_токен_с_hugging_face
MODEL_NAME=Qwen2.5-3B-Instruct-Q4_K_M.gguf
MODEL_REPO=bartowski/Qwen2.5-3B-Instruct-GGUF
```
Укажите ваш токен для HF с доступом к моделями.

`MODEL_NAME`(Название файла с весами модели на диске) и `MODEL_REPO`(Ссылка на репозиторий с весами модели) можно заменить на другую модель при условии её совместимости с установленными версиями `torch` и `huggingface_hub` 

### 3. Запуск

Для удобства предусмотрено два способа:

* **Для пользователя:** Запустите приложение через ярлык `Launch App` или напрямую через запуск файла `Start.vbs`(Это идентичные способы, ярлык вложен в папку проекта для удобства и может быть перенесён в удобное для пользователя место). Это запустит Backend и Frontend одновременно.

* **Для разработчика:**

    - Backend: `uvicorn app.api.main:app --reload`

    - Frontend: `streamlit run app/web/interface.py`

В консоли запустится Backend приложения с логами, в браузере откроется вкладка с интерфейсом приложения. Может понадобиться подождать некоторое время прежде чем Backend инициализирует модели перед началом работы.

### 4. Первый запуск

При первом запуске приложения streamlit может через консоль запросить разрешение на отправку уведомлений. Разрешение никак не сказывается на работоспособности приложений.

При первом запуске или смене модели может понадобиться некоторое время для скачивания весов модели.

Примерный вес моделей :

- Faster-Whisper - 140 Мб

- Pyannote - 350 Мб

- Qwen 2.5-3b-it-q4\_k\_m - 1.9 Гб

## Структура проекта

* `app/api/` - Backend часть (FastAPI, управление очередью задач).

* `app/ml/` - Ядро системы (движки транскрипции и анализа).

* `app/web/` - Пользовательский интерфейс (Streamlit).

* `data/uploads/` - Входящие аудиофайлы.

* `data/db/` - Json-файлы с результатами обработки.

* `data/outputs/` - Результаты обработки (TXT-протоколы).

* `models/` - Локальное хранилище весов LLM.

## Выходные данные

После обработки каждого файла создаются:

- `data/db/{timestamp}_{name}.json` - Структурированные данные.

- `data/output/{timestamp}_{name}_transcript.txt` - Текстовая расшифровка по ролям.

- `data/output/{timestamp}_{name}_analysys.txt` - Отчёт по расшифровке.

## **Метрики**.
Замеры проводились на тестовых файлах :

`tests/testing_audio_two_person(noisy).mp3` Аудиодорожка имеет длину 44 секунды и содержит диалог двух лиц с наложенным шумом.

`tests/testing_audio_single_person(noisy).mp3` Аудиодорожка имеет длину 31 секунду и содержит монолог одного лица с наложенным шумом.

`tests/testing_audio_single_person.mp3` Аудиодорожка имеет длину 31 секунду и содержит монолог одного лица без шума.

* **WER (Word Error Rate)** - 7.5%. Основной источник ошибок - фонетические интерпретации аббревеатур и профессиональные жаргонизмы.
* **DER (Diarization Error Rate)** - 5.5%. Диаризатор иногда не может распознать конкретный голос в условиях шума и поэтому обозначает его как Unknown
* **RTF (Real Time Factor)** - Первая обработка после запуска - (1.2) Последующие - (0.9).

* **ОС:** Windows 11

* **CPU:** Intel Core i5 2.7 GHz (Обработка велась на 12 ядрах)
* **GPU:** Вычисления производились на CPU из-за отсутствия отдельной видеокарты.

## Требования
### Описание проблемы
В современной корпоративной и образовательной среде протоколирование встреч и лекций вручную занимает значительное время и часто приводит к потере важных деталей. Существующие облачные решения (например, Otter.ai) зачастую не подходят из-за политики безопасности данных или высокой стоимости подписки. Существует потребность в инструменте, который обеспечивает полную конфиденциальность (работает локально) и автоматически генерирует структурированные отчеты.

### Целевая аудитория
* **Студенты и исследователи**: для автоматического преобразования лекций и интервью в структурированные конспекты.

* **Менеджеры проектов**: для фиксации договоренностей и списка задач после созвонов.

* **Секретари и администраторы**: как вспомогательный инструмент для составления официальных протоколов встреч.

### Пользовательские сценарии
* **"Пропустил встречу"**: Пользователь загружает аудиозапись прошедшего созвона и через несколько минут получает краткое резюме с ключевыми тезисами, не прослушивая запись целиком.

* **"Контроль задач"**: После планерки менеджер получает готовый список поручений (задач) с привязкой к контексту обсуждения.

* **"Архивация знаний"**: Сохранение расшифровок встреч в текстовом формате для быстрого поиска по ключевым словам в будущем.

### Ограничения
* **Аппаратные ресурсы**: Для работы нейросетей требуется современный многоядерный процессор (от 4 ядер) и желательно не менее 16 ГБ оперативной памяти для стабильной работы всех модулей одновременно.

* **Языковая поддержка**: Текущая версия оптимизирована для русского и английского языков.

* **Качество аудио**: Наличие сильных фоновых шумов или перебивание спикеров может снижать точность диаризации (DER) и распознавания речи (WER).

### Нефункциональные требования
* **Конфиденциальность**: Обработка данных должна происходить строго на локальной машине пользователя без отправки аудио во внешние облака.

* **Производительност**ь: Фактор реального времени (RTF) должен быть ниже или равен 1.0 (обработка не дольше длительности самой записи).

* **Автономность**: Приложение должно быть способно работать без постоянного подключения к интернету после загрузки необходимых весов моделей.

## MVP(Текущее состояние)
На данный момент программа имеет следующие характеристики :

* **Кросс-модальность**: Переход от аудио-сигнала к структурированному текстовому отчету в формате JSON и TXT.

* **Автономность**: Система работает локально, не передает данные на сторонние серверы, что обеспечивает конфиденциальность корпоративной информации.

* **Интеллектуальный слой**: Использование LLM (Large Language Model) позволяет не просто транскрибировать текст, а выделять смысловые блоки: задачи, дедлайны и список участников.

* **Адаптивность**: Динамическое распределение вычислительных мощностей в зависимости от характеристик CPU пользователя.

* **Поддержка слабых устройств**: В целях повышения доступности программы, в ней реализована поддержка ПК бюджетного сегмента и ноутбуков.

## Roadmap

* **Извлечение аудио из видеофайлов**. Сейчас программа получает на вход аудиофайл с записью совещания, что вынуждает пользователя отдельно извлекать аудио из записей созвонов. Планируется добавить автоматическое извлечение так как в основном записи встреч сохраняются в основном в видеоформате.

* **Оптимизация и поддержка GPU**. На данный момент корректную работу программы на GPU реализовать затруднительно в связи с отсутствием доступа к такому оборудованию. Доработка программы под использование дискретных GPU значительно ускорит обработку.

* **Автоматическая очистка временных файлов**. Программа при обработке каждого входного файла создаёт три : транскрипт, отчёт и json. Несмотря на то, что из-за формата файлов они не будут занимать много места на диске, планируется добавить автоматическое удаление файлов по истечению установленного пользователем времени.
 
* **Добавление асинхронности вычислений**. В текущей реализации интерфейс и обработка данных идут отдельными процессами, но данные обрабатываются последовательно по мере их добавления в очередь из-за ограниченности ресурсов системы. Планируется внедрение распределенной очереди задач на базе Redis/Celery для параллельной обработки потоков на серверных мощностях.

* **Автоматический экспорт списка задач**. В целях упрощения для пользователя работы с приложением планируется добавить автоматический экспорт списка задач в приложения с календарями или напоминаниями.
